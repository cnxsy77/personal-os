# Personal OS 表单弹窗化重构计划

## 已确认决策

- 计划、健康、财务、学习、工作台各保留一个醒目的 Add 按钮。
- 页面内不再直接展示录入表单，所有新增记录通过页面专属弹窗完成。
- 桌面端弹窗居中展示，移动端改为底部抽屉。
- 弹窗内部使用分段标签切换记录类型。
- 保存成功后关闭弹窗，列表立即刷新，并显示约 3 秒的成功提示。
- 校验失败时弹窗保持打开，错误信息留在对应表单内。
- 列表内保留状态修改，例如完成任务、切换训练状态、项目状态等。
- 概览页保持展示型，不承载复杂录入。
- 概览展示采用方案 C 的控制台明细骨架，加入方案 A 的“需要决策”面板和方案 B 的四个领域进度条。
- 顶部“快速记录”是全局入口：在功能页直接打开当前领域弹窗；在概览页先选择领域，再打开对应弹窗。

## 弹窗标签页

| 页面 | 弹窗标签页 |
| --- | --- |
| 计划 | 计划任务 |
| 健康 | 训练、身体指标 |
| 财务 | 收支、预算 |
| 学习 | 学习记录、学习路径、学习资料、周复盘 |
| 工作台 | 项目 |

## 页面展示结构

- 页面主体优先展示摘要指标和关键列表。
- 桌面端使用两栏仪表盘布局，左侧放核心摘要与记录，右侧放进度、分类或提醒。
- 移动端自动折叠为单栏，输入控件使用足够大的点击区域。
- 概览页顶部展示今日待办、本周训练、预算剩余和学习时长；中部展示健康、财务、学习、工作台四条进度；下方左侧放可筛选记录明细，右侧放今日优先、完成率和需要决策。
- 移动端概览折叠为单列，记录明细改为记录卡片，避免横向滚动和文字裁切。

## 实施顺序

1. 新增通用 `RecordDialog` 和 `Toast`，完成无障碍、键盘和响应式行为。
2. 重构计划页，迁移任务表单，并保留筛选和完成状态。
3. 重构健康页，迁移训练和身体指标表单，并保留训练状态切换。
4. 重构财务页，迁移收支和预算表单，并保留交易与预算摘要。
5. 重构学习页，迁移四类学习表单，并保留资料状态切换。
6. 重构工作台页，迁移项目表单，并保留项目状态切换。
7. 接入概览领域选择和全局快速记录，统一最终布局。

## 每步验证

- 每完成一个页面运行 `npm run test`。
- 每个阶段结束后运行 `npm run build` 和 `npm run lint`。
- 集成测试覆盖弹窗打开、标签切换、保存成功、校验失败和列表刷新。
- 每步使用桌面端和移动端视口检查布局，确认文字、按钮和输入框不重叠、不溢出。

## 最终验收

- 五个功能页都不再包含常驻录入表单。
- 每个 Add 入口都能打开正确的领域和标签页。
- 保存成功后数据进入列表，概览摘要同步变化。
- 状态切换仍发生在列表内。
- 键盘操作、焦点管理和减少动态效果偏好正常。
- 所有测试、构建和 lint 通过后推送远端。
